1. Osnovna tema i cilj

Suština: CAN protokol nema ugrađenu autentifikaciju ni enkripciju, pa zlonameran saobraćaj može da uđe u mrežu. Rad istražuje kako napraviti IDS koji prati CAN saobraćaj, prepoznaje anomalije/napade i reaguje.

Istraživačko pitanje: „Da li se jednostavan i objašnjiv IDS može koristiti za pouzdanu detekciju anomalija u CAN komunikaciji uz dovoljno malu latenciju za primenu u automobilskim sistemima?"

Tok: problem → ranjivosti → postojeći pristupi → implementacija i testiranje → poređenje tačnosti i performansi → predlog za lightweight / realtime IDS.

3. Plan rada — 3 dana jakog rada

📘 Dan 1 — Teorija + okruženje + EDA pogl. 2, 3, 4
  1. Postavka okruženja: Python venv, instalacije (pandas, numpy, scikit-learn, python-can, matplotlib).
  2. Preuzimanje Car-Hacking dataset-a: normal + DoS, fuzzy, spoofing, replay.
  3. Teorijske tačke za pogl. 2 i 3 (CAN frejm, ECU, tipovi napada) — direktno u rad.
  4. EDA: struktura csv-a, ključni ID-ovi, frekvencije, delta-t, raspodele.
  5. Vizuelizacije (matplotlib) — idu u pogl. 4.4 / 6.
⚙️ Dan 2 — Feature ekstrakcija + modeli pogl. 5, 6
  1. Feature extraction: Arbitration ID, DLC, payload (bajtovi 0–7), delta-t, windowing po ID-u.
  2. Rule-based detekcija (novi ID, prekoračena frekvencija, prevelik DLC).
  3. Statistička / anomaly detekcija (z-score, razlika delta-t po ID-u).
  4. ML — Isolation Forest (anomaly detekcija).
  5. ML — Random Forest (klasifikacija poznatih napada).
📊 Dan 3 — Evaluacija + zaključak + pisanje rada pogl. 6, 7
  1. Metrike: accuracy, precision, recall, F1, FPR + confusion matrix.
  2. Tabela poređenja pristupa + grafici (ROC, preciznost, latencija).
  3. Zaključak: odgovor na istraživačko pitanje, predlog za lightweight/realtime IDS.
  4. Šabloni poglavlja (teorija iz dana 1 + rezultati iz dana 2–3).
🎓 + Bonus — Lični doprinos (ako stignemo) pogl. 1.2
  • ESP32 + SN65HVD230 transceiver na OBD2 portu VW Pola 6R.
  • Firmware: TWAI drajver + SLCAN/LAWICEL protokol (preko USB serije).
  • Python: čitanje, filtriranje ID-jeva, spoofing komande (zaključavanje auta).
  • Provera da li ML radi na live saobraćaju — kao lični doprinos.

4. Vremenska skica / plan prioriteta (ukoliko je rok čvrst)

Optimalan scenario

  • Dan 1: okruženje + dataset + teorija → rad
  • Dan 2: feature + oba ML modela
  • Dan 3: evaluacija + zaključak + šabloni rada

Realna procena

  • Tehnički IDS (AI) deo: ~1.5–2 dana
  • Pravl auto / reverse engineering: varijabilno (rizik)
  • Pisanje rada: dodatnih 3–5 dana
  • 3 dana je realno samo za tehnički demo na datasetu.
